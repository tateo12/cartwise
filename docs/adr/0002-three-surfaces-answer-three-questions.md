# Three surfaces answer three different "cheapest" questions

"Where is it cheapest" has three defensible answers for the same basket — cheapest per Item (a 3-stop cherry-pick), cheapest 2-Stop Plan, and cheapest single Store — and they routinely disagree by several dollars. Rather than pick one globally, each is assigned to the surface whose question it actually answers: the **search bar** returns per-Item best, the **dashboard headline** returns the Store winner, and the **Savings ladder** returns multi-Stop Plans ranked by what they save.

The dashboard headline is deliberately **not** the lowest achievable number. A cherry-pick total is a spreadsheet, not a shopping trip; leading with a figure the user will almost never actually pay makes every subsequent number suspect. The lower totals remain one glance away in the ladder, so nothing is hidden — only de-emphasised.

## Consequences

- Do not "fix" the headline to show the cheapest possible total. That is the rejected option, not an oversight.
- The same Item can legitimately show a different recommended Store in the search bar than in the active Plan. This is correct, and the UI must make the reason legible rather than suppress one of the two.
