# Price sources are adapters, and every price carries its provenance

Only one US grocery chain relevant here publishes an official, free, public price API: **Kroger** (`api.kroger.com`), which covers Smith's, King Soopers, Fred Meyer, Ralphs, QFC, Fry's, Dillons and Harris Teeter from a single credential. Harmons, WinCo, Walmart, Costco, Target, Sprouts and Trader Joe's publish nothing equivalent. Their prices are obtainable only by scraping internal JSON endpoints, which violates site terms, sits behind commercial bot defence, and breaks without warning.

So Cartwise defines a single `PriceProvider` seam and ships two implementations: a real Kroger adapter (live when credentials are present) and a deterministic seeded provider for everything else. The optimizer, the view models and every component are written against `Offer`, not against a provider, so replacing a seeded chain with a real adapter later touches one file and no UI.

The non-negotiable half of this decision is **`Provenance` as a required field on every `Offer`**, rendered as a badge everywhere a price appears: `live`, `seed`, or `user`. An app that mixes real and placeholder prices without saying which is which is not a cheaper version of a price comparison app — it is a misleading one.

## Consequences

- Seeded prices are generated by a deterministic PRNG keyed on `(item, chain, day)`, never `Math.random`. Prices must be stable across restarts, or "price history" would be re-invented on every boot and the deal detector would be meaningless.
- Seeded providers report `stock: 'unknown'` rather than guessing availability. They genuinely cannot know it, and inventing it would be the same class of lie as inventing a price.
- Adding a scraper for another chain is a deliberate decision with legal and maintenance cost, not a natural next step. The seam makes it *possible*, not *advisable*.

## Amendment: seeded offers report no stock, and "configured" is not "live"

Two ways this decision was violated in the implementation:

**Seeded offers were inventing stock levels.** `stockFor` rolled a 4%
`out_of_stock` / 10% `low` for Kroger-chain products even though the offer was
`provenance: 'seed'` — so a Seed-badged Smith's price displayed "low stock", and
a fabricated `out_of_stock` removed the Item from that store's plan and
manufactured a forced extra stop out of nothing. Seeded offers now always report
`unknown`; only a live provider response sets a stock level.

**The sidebar claimed live prices it wasn't serving.** `fetchOffers` had no call
sites at all — the entire live path was dead code — while the sidebar showed
"Kroger API live" whenever credentials merely existed. There are now three
distinct states (no credentials / configured but not fetched / N live prices
loaded), an explicit refresh action that calls the provider and upserts offers
with `provenance: 'live'`, and a product the provider can't price keeps its
seeded offer rather than being deleted or zeroed — a missing live price is not
evidence the store stopped carrying the item.

## Amendment 2: live prices accumulate their own history

A deal verdict is computed from `price_history`. When a refresh overwrote only
the `offers` row, a real Kroger price was being scored against 90 days of
*seeded* history — so "Real low" and "Fake sale" on a live price were fiction
dressed as analysis.

`price_history` now carries a `provenance` column and every refresh appends
today's live price as a live point. Because that history starts empty, the app
says so explicitly (a caveat on My stores while fewer than 30 live points
exist) rather than implying a precision it does not have. Verdicts become
genuinely meaningful only as live points accumulate — one per product per
refresh per day.

Two implementation notes that cost real debugging time:

- **`create table if not exists` is a no-op on an existing table.** Adding a
  column to the DDL changes nothing for anyone who already has a database file;
  their queries fail with `no such column`. Schema changes need an explicit
  `pragma table_info` + `alter table` pass (`addMissingColumns`), and it must be
  verified against a genuinely old file — a fresh database builds the new schema
  from scratch and hides the bug completely.
- **A failed auth must not look like an empty result.** A 401 collapsing into
  "0 offers" made rejected credentials indistinguishable from "Kroger had no
  matching products". Providers now expose an optional `checkAuth()` so a caller
  can report the real reason.

### Correction to Amendment 2

Amendment 2 as first written described the problem correctly and only half-fixed
it. The `provenance` column was added and written to, but nothing ever **read**
it: `priceHistory()` did not select it and no consumer existed, so a live price
was still scored against 89 seeded points and still badged "Real low". A
write-only column is worse than no column, because it looks like the problem is
solved.

The completed fix: `PricePoint` carries `provenance`, `analyzeDeal` takes the
current offer's provenance, and

- a **seeded** price is judged against seeded history as before — internally
  consistent, and badged `Seed` throughout, so it stays a real verdict;
- a **live** price is judged against live points **only**;
- a live price with fewer than 14 live points returns a new verdict,
  **`no-basis`** ("No history yet"), and the UI suppresses the 90-day low and
  median rather than quoting figures drawn from placeholder data.

`no-basis` exists because the alternative was a confident-looking verdict with
nothing behind it. An honest "I can't tell yet" is more useful than a guess
wearing the same badge as a real answer.
